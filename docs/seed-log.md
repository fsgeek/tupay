## 2026-10-20: idea for later, not in scope (Tony, from a ChatGPT conversation)
Contracts that trace indeterminacy against performance. Some effects cannot absorb rollback (they have crossed an event horizon); some can. A contract that marks which effects may be issued speculatively, which observation collapses the uncertainty, and where the horizon is, would let a system speculate where rollback is improbable and pay for it only when it happens. Prior art: externally synchronous I/O (Nightingale et al., 2006: output commit is the horizon), Speculative Paxos, Zyzzyva. In tupay's v1 contract, C1.3's ack is the one horizon clause, and the fence ledger is the commit point that collapses the holder's indeterminacy. X1 (fenced reads) is where an unfenced read escapes the horizon with no ledger to reject it. Not to be started before the change experiments. Recorded so it is not lost.

## 2026-10-20: the indeterminacy idea, refined (ChatGPT via Tony; steward's reading)
Correction accepted: Speculator (SOSP '05) gates output on correctness; Rethink the Sync (OSDI '06) gates it on durability. The previous entry conflated them. Adopted as a candidate clause property: where H is the externalization point and C the event that resolves whether the authority was valid, H before C is unrecoverable speculation unless the clause names a compensation boundary; C before H may speculate freely inside. Candidate clause vocabulary for a later contract version: provisional effect, validation event, event horizon, compensation boundary; a clause as (allowed speculation, validation predicate, externalization boundary), with a failure-model cell supplying when validation can fail. Steward's observation: X1 (fenced reads) already is "move the horizon across the resolution point": an unfenced read has H before C with no ledger to reject it; fencing moves C in front of H. That wording goes into X1's pre-registration. Nothing is changed in contract v1.
