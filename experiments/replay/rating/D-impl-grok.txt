The configuration path is **(c)**. On election the coordinator appends nothing of its own epoch, and a change waits only until the last configuration entry is committed.

`becomeLeader` sets leader state, emits `Elected`, and broadcasts. It does not append a journal entry. `processRequests` then blocks only on the previous configuration:

```
if p.Stage == "wait" {
    if m.ConfigIndex > m.Commit {
        return
    }
```

The README states the same rule: "Every requested change waits for the last configuration entry in the local journal to be committed, including inherited entries. No extra election no-op, joint consensus, commitment barrier from another specification, or special repair of the published membership algorithm is added."

**R4 before: no.** The pre-run Concerns section flags a probe and then withholds the claim: "This is a concern, not an established diagnosis." It does not assert that the specified design violates J1.1, J1.5, or persistence of committed entries.

**R4 after: no.** After running, the text says "No unmutated safety violation was witnessed" and that the reading-only concern "remains unresolved" because "None of the shared executions discriminated that concern."
